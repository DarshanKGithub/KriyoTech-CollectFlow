# Payment Gateway

Razorpay is configured only with server environment variables `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, and `RAZORPAY_API_BASE_URL`. Never send secrets to the browser. Create Orders server-side, verify checkout signatures using HMAC, verify webhook signatures on raw request bytes, and deduplicate events by event ID. Only a captured/paid verified event can activate a subscription. Keep raw payloads access-controlled and masked in UI.

When configured, the tenant billing view creates an Order server-side. Checkout callbacks are HMAC-checked and followed by an authenticated server-side fetch requiring captured state, expected order ID, amount, and currency. Signed webhooks are deduplicated, saved with their raw payload, and processed with bounded Celery retries. A verified captured payment activates the selected plan and creates a billing receipt. Until all three secrets are present, checkout and refunds stay disabled. Internal billing admins can record an offline payment with a reason and reference. Refund state and subscription impact change only after a verified provider refund event. Automated bank reconciliation is still separate from gateway billing.

The flow follows Razorpay's guidance to keep the API secret server-side, verify Checkout signatures using a server-stored Order ID, and confirm captured status using a trusted server-side source. See [Razorpay's Python integration steps](https://razorpay.com/docs/server-integration/python/test-app/) and [Razorpay's security checklist](https://razorpay.com/security/checklist).
